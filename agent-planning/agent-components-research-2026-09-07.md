# Agent 组成与研究方向：补充地图

日期：2026-09-07。状态：研究与讨论草案，未确认团队投入。沿用 grill-with-docs：公开证据、助手判断与用户决定分开。

## 先区分分类层级

现有 sandbox、harness、memory/context、multi-agent、安全不是同级目录：sandbox 是执行基础设施，harness 是运行与组织层，memory/context 是信息状态能力，multi-agent 是协作策略，安全是横向要求。下述是工作分类提案，未写入项目术语表。

软件 agent 的参考闭环：目标与约束 → 观察环境/取得信息 → 形成或调整行动 → 工具执行 → 观察结果与验证 → 继续、求助或结束。执行历史可进入记忆，也可经过验证用于训练。并非每个 agent 都需要独立 planner、world model 或多 agent。

## 值得补充的七类问题

| 类别 | 核心研究问题 | 与当前方向的关系 |
|---|---|---|
| 决策、规划与推理预算 | 何时规划或重规划，何时搜索、验证、求助或停止；如何处理未知与错误前提 | 模型策略与 harness 共同承担；多 agent 只是可能的策略 |
| 工具与动作接口 | 大工具集如何发现、选择和组合；API/CLI/代码执行/GUI 如何选；错误怎样帮助恢复 | MCP 等协议是接入基础，工具可用性与调用质量还需评估 |
| 环境感知与多模态交互 | 将截图、DOM、文档映射为可信状态和动作目标；页面变化后如何判断动作实际成功 | Sandbox 提供环境，感知与交互决定能否有效操作它 |
| 评估、验证与可观测性 | 何为完成，如何验收外部状态；怎样定位模型/工具/记忆/环境失败，防止奖励投机 | 横跨现有全部方向；离线评估、运行时 verifier 和诊断日志不同 |
| 学习与适配 | 从轨迹生成数据、分配奖励与归因；改善提示/工具/记忆或训练模型；适应新环境与模型 | 经验记忆不等于参数更新；训练会连接环境基础设施与 harness |
| 人机协作与任务控制 | 何时澄清、展示证据、请求接管；用户中途改变目标后如何更新约束并继续 | 不只是审批 UI，与可用性、可靠性和安全均有关 |
| 推理服务与系统经济性 | 模型路由、缓存、批处理与异步调度如何影响任务质量/成本/尾延迟 | 与通用 serving 有交集，需证明 agent 特有负载值得单独优化 |

## 一手证据与边界

- 工具接口是独立优化对象：Anthropic 讨论工具选择、命名、返回信息、token效率和工具评估，说明协议接通不等于可用。[Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)
- 任务轨迹不等于外部结果：agent 评估需检查实际 outcome，组合多种验收器并重复试验。[Demystifying evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)
- OSWorld 提供真实计算机环境中的开放式任务评估，支撑 GUI/多模态交互作为独立能力问题；不能将其成绩外推到所有业务系统。[OSWorld](https://osworld-v1.xlang.ai/)
- Agent Lightning v1.0（2026-08-18）研究部署 harness 参与后训练，涉及样本组织、优势估计和调度。它证明这一研究范式有可复现案例，不代表任意业务都适合 RL。[论文](https://arxiv.org/abs/2608.17528)
- 规划、反馈和工具交互的参考框架可见官方工程实践；不据此断言必须有固定 planner 模块。[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)

## 关键边界

- Memory 改变下一次执行可获得的经验；训练改变模型参数；两者可组合但不是一项能力。
- Offline eval 比较版本；runtime verifier 决定当前产物能否接受；observability 帮助解释发生了什么。
- Sandbox 管执行环境；environment/benchmark 还要定义任务、状态、反馈与成功条件。
- MCP/协议互操作属于工具接入基础，不能代表 agent 会选对工具或正确完成任务。
- Skills 属于可复用知识和过程的交付方式；是否构成独立研究主题取决于自动提炼、组合、适用性验证等具体问题。
- World model 对需要预测行动后果的场景有意义，但不预设每个软件 agent 都需要独立世界模型。具身/机器人若进入范围，还需动作控制和物理安全专题。

## 对团队的候选判断

建议优先补齐认知地图中的三项：评估/验证/数据闭环；工具与环境交互；学习与适配。理由是它们可以分别检验已有投入、解释环境内行动失败、连接已有经验记忆与训练环境积累。这里的优先是后续调研顺序，不是资源投入排序。
